# Admin Management System Documentation

## Overview

This is a comprehensive Administrator Management API and Dashboard for the Tomobilty car rental platform. The system provides full CRUD operations and advanced management capabilities with enterprise-level security.

## 🔐 Security Features

### Authentication & Authorization
- **JWT-based authentication** with access and refresh tokens
- **Role-based access control (RBAC)** - Only users with `ADMIN` role can access admin routes
- **403 Forbidden** responses for non-admin users
- **Rate limiting** on all admin endpoints (1000 requests per 15 minutes)
- **Audit logging** for ALL admin actions (who did what, when)

### Input Validation
- **Zod schema validation** for all inputs
- **SQL injection prevention** via Prisma ORM
- **Request size limits** via Express middleware
- **Sanitization** of all user inputs

## 📊 Backend API Endpoints

### Base URL
```
http://localhost:5000/api/admin
```

### Authentication Required
All admin routes require:
```
Authorization: Bearer <JWT_TOKEN>
```

## 1. USER MANAGEMENT

### GET /admin/users
List all users with pagination, search, and filtering.

**Query Parameters:**
- `page` (number, default: 1)
- `limit` (number, default: 20, max: 100)
- `search` (string) - Search by email, name, phone
- `role` (CLIENT | ADMIN | AGENT)
- `emailVerified` (boolean)
- `phoneVerified` (boolean)
- `startDate` (ISO datetime)
- `endDate` (ISO datetime)
- `sortBy` (string)
- `sortOrder` (asc | desc)

**Response:**
```json
{
  "success": true,
  "data": {
    "users": [...],
    "pagination": {
      "page": 1,
      "limit": 20,
      "total": 150,
      "totalPages": 8
    }
  }
}
```

### GET /admin/users/:id
Get detailed user information including all relations.

**Response includes:**
- User profile
- Loyalty account with tier and transactions
- Recent bookings (last 10)
- Recent payments (last 10)
- Reviews
- Documents
- Counts of all related entities

### POST /admin/users
Create a new user (any role).

**Body:**
```json
{
  "email": "user@example.com",
  "mot_de_passe": "SecurePass123",
  "nom": "Doe",
  "prenom": "John",
  "telephone": "+212 6XXXXXXXX",
  "role": "CLIENT",
  "adresse": "123 Street, City"
}
```

### PUT /admin/users/:id
Update user details, change roles, verify email/phone manually.

### DELETE /admin/users/:id
Delete user (soft delete recommended).

### GET /admin/users/:id/activity
Get user activity log (bookings history, payments, loyalty transactions).

### POST /admin/users/:id/reset-password
Force password reset for a user.

**Body:**
```json
{
  "new_password": "NewSecurePass123"
}
```

### PUT /admin/users/:id/suspend
Suspend or unsuspend user account.

**Body:**
```json
{
  "suspended": true
}
```

### GET /admin/users/stats
Get user statistics.

**Response:**
```json
{
  "success": true,
  "data": {
    "totalUsers": 1500,
    "usersByRole": [...],
    "verifiedUsers": 1200,
    "unverifiedUsers": 300,
    "newUsersThisMonth": 45
  }
}
```

## 🛠️ Setup Instructions

### 1. Database Setup

The admin system requires two new tables:

```bash
# The schema has been updated with AuditLog and SystemSetting models
# Generate Prisma client
npm run prisma:generate

# Push schema to database (if using db push)
# Note: Use environment variable for connection
$env:DATABASE_URL = "your_connection_string"
npx prisma db push
```

### 2. Install Dependencies

```bash
npm install zod express-rate-limit
```

### 3. Environment Variables

Ensure your `.env` file has:

```env
DATABASE_URL=your_database_url
DIRECT_URL=your_direct_database_url
JWT_SECRET=your_jwt_secret
PORT=5000
NEXT_PUBLIC_API_URL=http://localhost:5000/api
```

### 4. Start the Backend

```bash
npm run api:dev
```

### 5. Start the Frontend

```bash
npm run dev
```

### 6. Create Admin User

You need at least one admin user. You can:

**Option A: Update existing user via database:**
```sql
UPDATE users SET role = 'ADMIN' WHERE email = 'your@email.com';
```

**Option B: Use the registration endpoint and manually update:**
1. Register normally at `/inscription`
2. Update role in database to 'ADMIN'

## 🔒 Security Best Practices

### For Production:

1. **Enable HTTPS** - Never use HTTP in production
2. **Secure JWT_SECRET** - Use a strong, random secret (32+ characters)
3. **Rate Limiting** - Adjust limits based on your needs
4. **CORS Configuration** - Restrict to your frontend domain only
5. **Environment Variables** - Never commit `.env` files
6. **Database Backups** - Regular automated backups
7. **Audit Log Retention** - Archive old logs periodically
8. **SSL/TLS** - Use proper certificates (not self-signed)
9. **Input Validation** - Always validate on both frontend and backend
10. **Error Messages** - Don't expose sensitive information in errors

### Middleware Stack:

```javascript
// Applied to all /admin routes:
1. authenticate - Verify JWT token
2. requireAdmin - Check user role is ADMIN
3. adminRateLimiter - Rate limiting (1000 req/15min)
4. validateQuery/Body/Params - Zod validation
5. auditLog - Log all actions
6. captureOldValues - For UPDATE/DELETE operations
```

## 📝 Audit Logging

All admin actions are automatically logged with:

- **admin_id** - Who performed the action
- **action** - What action (CREATE, UPDATE, DELETE, etc.)
- **entity_type** - What entity (User, Car, Booking, etc.)
- **entity_id** - Which specific record
- **old_values** - Previous state (for updates/deletes)
- **new_values** - New state (for creates/updates)
- **ip_address** - Request IP
- **user_agent** - Browser/client info
- **created_at** - Timestamp

### Viewing Audit Logs

```javascript
// Future endpoint (to be implemented):
```

## 📊 Database Schema Additions

### AuditLog Table
```prisma
model AuditLog {
  id          Int      @id @default(autoincrement())
  admin_id    Int
  action      String   @db.VarChar(50)
  entity_type String   @db.VarChar(50)
  entity_id   Int?
  old_values  String?
  new_values  String?
  ip_address  String?  @db.VarChar(45)
  user_agent  String?
  created_at  DateTime @default(now())

  @@index([admin_id])
  @@index([entity_type])
  @@index([created_at])
  @@map("audit_logs")
}
```

### SystemSetting Table
```prisma
model SystemSetting {
  id         Int      @id @default(autoincrement())
  key        String   @unique @db.VarChar(100)
  value      String
  category   String   @db.VarChar(50)
  updated_at DateTime @default(now()) @updatedAt
  updated_by Int?

  @@map("system_settings")
}
```
